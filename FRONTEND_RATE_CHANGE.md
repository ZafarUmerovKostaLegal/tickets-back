# Фронт: смена ставки пользователя в проекте с конкретной даты

Инструкция для фронтенда по фиче «изменить ставку конкретного пользователя в
конкретном проекте начиная с выбранного дня». До выбранного дня расчёт идёт по
старой ставке, начиная с выбранного дня — по новой.

Бэкенд уже всё считает сам (проратирование по периодам). Фронту нужно вызвать
один новый эндпоинт и обновить UI.

---

## 1. Новый эндпоинт

```
POST /api/v1/users/{authUserId}/hourly-rates/change-from
```

Альтернативный путь (тот же обработчик, если уже используете этот префикс):

```
POST /api/v1/time-tracking/users/{authUserId}/hourly-rates/change-from
```

### Тело запроса (JSON)

| Поле                | Тип     | Обяз. | Описание                                                        |
| ------------------- | ------- | ----- | --------------------------------------------------------------- |
| `rateKind`          | string  | да    | `"billable"` (оплачиваемая) или `"cost"` (себестоимость)        |
| `appliesToProjectId`| string  | да    | ID проекта, для которого меняем ставку пользователя             |
| `effectiveFrom`     | string  | да    | Дата (формат `YYYY-MM-DD`). С этого дня действует новая ставка   |
| `amount`            | number  | да    | Новая ставка (> 0)                                              |
| `currency`          | string  | нет   | Валюта, по умолчанию `"USD"`. Должна совпадать с валютой проекта |

Пример:

```json
{
  "rateKind": "billable",
  "appliesToProjectId": "8f3c...-проект",
  "effectiveFrom": "2024-06-01",
  "amount": 140,
  "currency": "USD"
}
```

### Ответ (200)

```json
{
  "new_rate":     { "id": "...", "amount": "140.0000", "valid_from": "2024-06-01", "valid_to": null,  "applies_to_project_id": "8f3c..." },
  "closed_rate":  { "id": "...", "amount": "100.0000", "valid_from": null,         "valid_to": "2024-05-31" },
  "before_rate":  null,
  "updated_rate": null
}
```

Что значат поля ответа (любое может быть `null`):

- `new_rate` — всегда есть (кроме случая обновления на месте): новый период с новой
  ставкой, действует с `effectiveFrom`.
- `closed_rate` — прежний период, закрытый днём раньше `effectiveFrom`.
- `before_rate` — период «до даты», созданный автоматически при **первом**
  переопределении ставки в проекте (чтобы расчёт до даты не обнулился).
- `updated_rate` — если меняли ставку ровно с даты начала существующего периода,
  он просто обновляется на месте (тогда `new_rate` указывает на ту же запись).

Фронту не нужно различать эти случаи — достаточно после успеха перезапросить
список ставок проекта и отчёты.

### Коды ошибок

- `400` — некорректные данные (валюта/тип/сумма ≤ 0, не указан проект и т.п.),
  `detail` содержит человекочитаемый текст на русском.
- `403` — недостаточно прав.
- `404` — проект или пользователь не найден.

---

## 2. Права доступа (роли)

- `billable` — менять могут: **Главный администратор, Администратор, Партнёр**.
- `cost` — менять могут: **Главный администратор, Администратор, Партнёр** (те же).

Кнопку/форму смены ставки показывать только этим ролям. Для остальных — скрывать.

---

## 3. Что сделать в UI

1. В карточке ставок пользователя по проекту добавить действие
   **«Изменить ставку с даты»**.
2. Форма с полями:
   - дата начала действия новой ставки (`effectiveFrom`, date-picker);
   - новая сумма (`amount`, number > 0);
   - валюта (`currency`) — по умолчанию валюта проекта, лучше брать её автоматически
     и не давать менять руками;
   - тип ставки (`rateKind`) — обычно предопределён контекстом экрана
     (оплачиваемая/себестоимость).
3. На submit — `POST .../hourly-rates/change-from` с телом выше.
4. После успешного ответа:
   - перезапросить список ставок:
     `GET /api/v1/users/{authUserId}/hourly-rates?kind=billable&projectId={projectId}`;
   - перезагрузить отчёты/дашборд (суммы пересчитываются на бэке автоматически).
5. Ошибки `400/403/404` — показать `detail` из ответа в тосте/нотификации.

### Подсказка по тексту в UI

Покажите пользователю предпросмотр логики, например:
«До 31.05.2024 — старая ставка, с 01.06.2024 — 140 USD».

---

## 4. Чем это отличается от обычного создания/редактирования ставки

Раньше, чтобы «сменить ставку с даты», нужно было вручную:

1. закрыть старую ставку (`PATCH` → `validTo = день-1`);
2. создать новую (`POST` → `validFrom = день`).

Это было легко сделать неправильно (пересечения периодов → ошибка 400, либо
обнуление расчёта до даты при первом проектном переопределении).

Новый эндпоинт делает это атомарно и корректно за один вызов. **Используйте его**
вместо ручной связки `PATCH` + `POST` для сценария «сменить с даты».

Существующие эндпоинты (`POST /hourly-rates`, `PATCH /hourly-rates/{id}`,
`DELETE`, `GET`) продолжают работать как раньше — для ручного управления
периодами.

---

## 5. Важный нюанс расчёта (для понимания)

Если у проекта появляется хотя бы одна персональная ставка пользователя, то
общая (не привязанная к проекту) ставка для этого проекта больше не применяется.
Поэтому при **первом** переопределении в проекте бэкенд сам создаёт период
«до даты» (`before_rate`) с прежней действующей суммой — чтобы расчёт до выбранной
даты остался верным. Фронту делать для этого ничего не нужно.
